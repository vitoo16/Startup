# P04-BIZ-01 — Catalog-driven business launch UI

**Date:** 2026-11-03. **Owner model:** GPT-6 Technical Director.
**Baseline:** `41f66182ef5752d877b4e135cc0d0d886ac9c422`. **Lane:** owner-authorized `main`.

## Problem / acceptance scope

The original four business definitions were already authoritative in
`ContentCatalog` and `BusinessOperationsProjection.LaunchOptions`, but
`BusinessManagementOverlay.Build()` still authored four individual
`AddLaunch` buttons and callbacks by literal ID. Expanding the GDD's
business catalog would require another UI-specific launch path for each
business. The fixed `BusinessType` switch duplicated Vietnamese names
already present in `DashboardLocalizationCatalog`.

## Implemented

1. Added the immutable, authored `OperationMode` field to each
   `BusinessLaunchReadiness`; all other offer fields continue to come from
   the exact current catalog and state revision.
2. Added `LifeScreenViewController.LaunchBusiness(definitionId)` as a
   catalog-based public entry point. It delegates to the unchanged
   `LaunchAuthoredBusiness` and `FirstPlayableFlow.LaunchBusiness`, with
   the authored revision and minimum investment. Preserved all four
   legacy parameterless UnityEvent callbacks for existing serialized scenes.
3. Replaced the hardcoded four launch buttons with a nested, size-fitting,
   vertically laid out list rendered from `operations.LaunchOptions`.
   Buttons are cached by definition ID, reordered deterministically,
   removed if no longer present, and disabled on read-model ineligibility.
   Each option displays localized name, minimum startup capital,
   operation mode, optional required owner minutes, and block reason.
4. The owned-business name also resolves from the same Vietnamese
   localization manifest, instead of a separate `BusinessType` display
   switch. No new art or copy is generated.
5. Updated the existing FirstPlayable static validator to require
   the new catalog-driven list **and** the real command dispatch. It
   no longer requires the obsolete four-ID `AddLaunch` implementation.
6. Added a Python source contract to Engine-free CI and extended the
   existing real M9 `EconomicChecks` to verify that launch options are
   in authored catalog order and expose the exact revision, name key,
   mode and minimum capital for all four currently supported businesses.

## Boundaries / release gating

- **No new business type is falsely shipped by this slice.** The four
  authoritative businesses remain Online Store, Home Food Preorder,
  Freelance Service and Coffee Kiosk. The GDD's Agency/Café/Fashion
  expansion needs distinct economic profiles, operating time, affinity,
  content archival and deterministic replay cases in its own slice.
- No second economy, manager simulation, special discount, implicit
  transaction, new command ID, save migration or balance values were
  introduced. Eligibility previews are advisory; the engine still rejects
  stale or invalid submissions.
- The serialized Unity catalog, string tables and scene YAML are **not**
  regenerated by GitHub source edits. Unity Editor, 9:16 mobile, 200%
  text scale and touch visual QA remain deferred as explicitly requested.
- The test-source matcher bug from the previous Career History session
