# ADR-009 — Versioned save generations and recovery

Status: implementation contract proposed under M1-T01; dependency gate pending. Date: 2026-09-30.

Context: Interrupted mobile writes, schema changes, and presentation replay must preserve a coherent simulation checkpoint.

Decision: Save all authoritative state and receipts as one versioned envelope with generation/checksum. Write/flush/validate temp, use tested platform replacement, retain the previous valid generation, and read back before publishing a committed outcome. Temp alone is never a commit. If replacement lacks required guarantees, implement a tested two-slot generation/commit-marker fallback. Protect valid backup from corrupt primary.

Restore validates primary then explicitly reports any rollback to backup. Future schemas or unsupported content are preserved and rejected, never silently downgraded. Sequential migrations increment one version, operate on copies, validate, and preserve originals until replacement. Use a clearly synthetic v0 fixture for the initial migration runner. Every later schema change requires version and fixture, including additions.

Consequence: Initial save contains empty reserved collections for deferred systems, current activity, pending choice, RNG/deck, command/operation receipts, and playback cursor. Timestamps are diagnostic only. Mobile filesystem durability, JSON serializer/AOT stripping, and low-storage behavior require device evidence; backup rollback cannot guarantee preservation of newer corrupt data.

Verification required: round-trip, synthetic older fixture, future-version preservation, corrupt primary/backup, writes interrupted at each stage, ambiguous acknowledgement, and deterministic continuation. See [contracts](../architecture/FIRST_PLAYABLE_CONTRACTS.md). No save implementation or Unity test result claimed.

H1 recovery exception (2026-10-01): [ADR-003](ADR-003-transactional-outcomes.md) permits a same-generation receipt compatibility checkpoint through a dedicated store capability. It can replace historical internal batch-child IDs only, after comparing the complete expected checkpoint under the writer lock. Every other serialized field must match. It persists resolved ownership in primary and backup without a gameplay command, schema change or revision increment. Normal commit rules remain revision +1. Unknown ownership, unsupported primary content and stale/concurrent resolutions cannot use this operation to overwrite state.

Validation precedence for R2: validate existing intrinsic structure across the whole DTO before checking content versions/IDs/revisions. Then validate all checks whose referenced definitions are available, deferring compatibility exceptions until those checks finish. Unavailable definitions remain unsupported; existing negative values, invalid IDs/cursors/fractions/receipts and known-definition inconsistency remain corruption. No new M2 restore invariants are introduced by this ordering repair.

M2 provenance enforcement (2026-10-01): committed receipts are the complete ordered command history in this foundation; no receipt pruning is supported. Intrinsic validation binds their canonical payloads, contiguous revisions and durations to the activity timeline and current cursor before compatibility checks. Entity sequence numbers are global across kinds, including retained typed references in ledger/grants/history. `JsonSaveSerializer` requires an `IRestoreStateValidator` Core port, supplied by `GameSession.CreateRestoreValidator()` from Simulation, for both serialization and deserialization. Infrastructure still depends only on Core. The verifier reconstructs a detached candidate using the runtime engine and compares identity/reward/history/scheduler provenance, without repairing or publishing the saved state. Known scheduler history is verified independently of unavailable unrelated content; checks that require missing career revisions/scenes remain compatibility failures. Schema/envelope/DTO version 1 and the synthetic-v0 migration are unchanged. See [M2 follow-up evidence](../evidence/M0-T04/M2-RESTORE-PROVENANCE.md).
